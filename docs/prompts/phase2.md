=====================================================
PHASE 2 : DEMANDES DE MESSE ET MESSAGES PRIVÉS DES PAROISSIENS
=====================================================

2.1 DEMANDES DE MESSE (intentions)
- Table intentions_messe : paroisse_id, code_suivi (unique, 10 caractères aléatoires générés avec un générateur cryptographique dans l'alphabet sans caractères ambigus 23456789ABCDEFGHJKMNPQRSTUVWXYZ, jamais séquentiel), nom_demandeur (obligatoire, 100), telephone (facultatif, format validé, 30), type (defunt, action_de_grace, sante, anniversaire_deces, autre), intention (texte, 300, obligatoire), date_souhaitee (facultative, aujourd'hui ou futur), horaire_id (facultatif, une messe de cette paroisse), statut (recue, confirmee, programmee, celebree, refusee, annulee), date_programmee (nullable), horaire_programme_id (nullable), motif_refus (nullable, 200), traitee_par (user_id nullable), timestamps. Index (paroisse_id, statut, created_at) et unique sur code_suivi.
- Structure prête pour un paiement futur (ne rien implémenter) : documente dans SYNTHESE.md où s'ajouterait un statut de paiement.
- Public : formulaire sur /p/{slug}/intentions/nouvelle (champs ci-dessus), texte de confidentialité sous le formulaire ("Vos informations sont lues uniquement par l'équipe de la paroisse et supprimées 90 jours après la célébration"). À l'envoi : page de confirmation affichant le code de suivi en grand, avec bouton Copier et conseil de le noter ou de le capturer ; le code n'est affiché qu'une fois à cet écran. Suivi : /p/{slug}/intentions/suivi, on saisit le code ; affiche uniquement le statut, la date et l'heure programmées, le motif de refus, jamais le texte de l'intention ni le nom ni le téléphone. Un code d'une autre paroisse ou inconnu donne le même message neutre. Rate limiting strict sur le suivi (anti-devinette) et sur la création (5 par heure et par IP).
- Admin (permission intentions.gerer) : liste filtrable par statut et date, avec compteur de nouvelles demandes dans le menu ; détail ; actions : confirmer, programmer (choisir une date et une messe de l'horaire), marquer célébrée, refuser avec motif, annuler ; transitions de statut valides uniquement (par exemple une demande célébrée ne peut plus être refusée) ; bouton "Écrire sur WhatsApp" (lien wa.me avec message prérempli) si un téléphone est présent ; "Feuille des intentions" imprimable pour une date donnée (liste des intentions programmées ce jour-là, groupées par messe, avec style d'impression).
- Données : commande planifiée intentions:purger qui anonymise (efface nom et téléphone, garde type et statut) les demandes célébrées, refusées ou annulées depuis plus de 90 jours (valeur en config).

2.2 MESSAGES PRIVÉS (avis)
- Table messages_prives : paroisse_id, sujet (suggestion, remerciement, difficulte, autre), message (texte, 2000, obligatoire), nom (facultatif, 100), contact (facultatif, 100), souhaite_reponse (boolean), statut (nouveau, lu, traite, archive), lu_par (user_id nullable), timestamps. Aucune IP stockée.
- Public : formulaire sur /p/{slug}/contact ("Écrire en privé à la paroisse"), anonymat explicite (nom et contact facultatifs), texte de confidentialité clair, page de confirmation simple (sans code). Mêmes protections anti-spam que les demandes de messe.
- Admin : visible uniquement pour l'admin de la paroisse (et le super_admin) et pour les secrétaires ayant explicitement la permission messages.lire ; sinon 403. Liste avec filtres par statut et sujet, compteur de non-lus dans le menu (seulement pour ceux qui ont le droit), détail avec changement de statut, suppression définitive autorisée à l'admin. Si un contact de type téléphone est fourni et souhaite_reponse est vrai : lien WhatsApp ou tel: ; sinon rien. Archivage automatique des messages traités depuis plus de 12 mois (commande planifiée, valeur en config).
- Le contenu d'un message ne doit apparaître nulle part ailleurs (ni dashboard public, ni cache, ni logs, ni notification).

2.3 TESTS PHASE 2 : validation et limites de chaque champ ; code de suivi (unicité, alphabet, jamais en séquence) ; suivi qui ne divulgue rien de personnel ni d'une autre paroisse ; rate limiting (création, suivi) ; honeypot et délai minimal ; transitions de statut valides et invalides ; permissions (secrétaire sans intentions.gerer : 403 ; sans messages.lire : 403 ; admin A ne voit rien de B : 404) ; purge et anonymisation ; archivage des messages ; aucune donnée personnelle dans les logs (test qui capture les logs) ; rendu Vue de toutes les nouvelles pages.
